## What I build

I build practical tools that make messy data, business processes, and AI systems easier to understand and trust. The projects below show how I define problems, design workflows, test failure cases, and turn ideas into working results.

> Some projects are generalized or recreated with synthetic data to respect employer and client confidentiality. AI coding tools may accelerate implementation; I remain responsible for the problem definition, architecture, testing, review, and final decisions.

| **[Integration-in-a-box](https://ansarbuilds.dev/#project/integration)** ↗ | Two made-up companies, the connector between them, real logins (Keycloak, OAuth 2.0), signed webhooks, and ten deliberate failures with a runbook for each. Runs with Docker. [Code, case study and runbook](https://github.com/kmsmohamedansar/integration-in-a-box). |
| **[Analytics assistant: rules vs AI](https://ansarbuilds.dev/#project/analytics-assistant)** ↗ | A rule-based brain and a local AI model (Ollama) answer the same 30 questions about a year of grocery sales through the same six MCP tools. Both scored. [Code and results](https://github.com/kmsmohamedansar/analytics-assistant). |
| **[Customer data delivery](https://ansarbuilds.dev/#project/data-delivery)** ↗ | Messy weekly sales files from several pharmacies become one clean, tested table, delivered only if every check passes. DuckDB, dbt, Dagster. [Code and runbook](https://github.com/kmsmohamedansar/data-delivery). |
| **[Catalogue checker](https://ansarbuilds.dev/#project/catalogue-checker)** ↗ | Which grocery products are filed in the wrong category? Three checkers, from keyword match to a large zero-shot model, tested on Open Food Facts with 50 planted errors. [Code and results](https://github.com/kmsmohamedansar/catalogue-checker). |

## Built with AI

I build internal tools and agent-facing infrastructure with AI coding agents (Claude Code, Cursor) and the Model Context Protocol: MCP servers for IDE agents, and Chrome (MV3) side-panel extensions for retail data operations. That work lives in private repos, so the case studies are written up generically, and the two public repos below recreate the patterns with synthetic data.

| | |
|---|---|
| **[Case studies](https://ansarbuilds.dev/#projects)** ↗ | MCP server for analytics context, an in-scope checker, the Sidecar Chrome extension, a Next.js health dashboard and a category-copilot prototype, each with a flow diagram. |
| **[mcp-analytics-stub](https://github.com/kmsmohamedansar/mcp-analytics-stub)** ↗ | Minimal TypeScript MCP server: a resolver tool and a context tool returning synthetic JSON, with schema validation and tests. |
| **[mv3-sidepanel-starter](https://github.com/kmsmohamedansar/mv3-sidepanel-starter)** ↗ | Starter Chrome MV3 side panel: paste IDs, apply mock rules, download a CSV. Rules are a pure function, unit-tested with Node. |
| **[Experiments](https://ansarbuilds.dev/#ai)** ↗ | A 3D solar system with real orbital mechanics, a terminal that answers as me, and a WebGL star field, all built with an AI pair programmer. |
